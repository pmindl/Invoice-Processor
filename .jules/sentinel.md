## 2024-03-06 - [Prevent Info Leakage in Error Handlers]
**Vulnerability:** API routes (`/api/ingest/email`, `/api/ingest/upload`, `/api/export`, `/api/trigger`) were catching exceptions and directly returning `(error as Error).message` in HTTP 500 JSON responses.
**Learning:** Returning raw error messages directly to the client can inadvertently expose sensitive internal system details, stack traces, or configuration data depending on the underlying failure. This represents a medium-priority information leakage risk.
**Prevention:** Catch blocks must use `console.error` (or a dedicated logger) to record the raw error details server-side for debugging, while always returning a generic, safe message like `'Internal Server Error'` to the client.
