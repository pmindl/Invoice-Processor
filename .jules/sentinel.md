## 2025-03-11 - [Timing Attacks & Fail-Open Vulnerability in API Auth]
**Vulnerability:** API routes (`/api/export`, `/api/process`, `/api/cron`) were vulnerable to timing attacks due to the use of standard string comparison (`!==`) for `APP_API_KEY`. Additionally, if `APP_API_KEY` was missing from the environment, the comparison would fail open in some scenarios or lead to undefined behavior, posing a severe security risk.
**Learning:** Standard string comparison operators (`===`, `!==`) compare character by character and return early on the first mismatch, allowing an attacker to deduce the secret key by measuring the response time. Furthermore, missing environment variables should never result in a fail-open state or undefined behavior during authentication checks.
**Prevention:** Implement and use a constant-time comparison utility (`secureCompare` via `crypto.timingSafeEqual` by hashing inputs first) for all secure token and API key validations. Always check if critical environment variables (like `APP_API_KEY`) are defined and explicitly return a 500 Internal Server Error if they are missing to ensure a fail-secure posture.
## 2024-03-18 - Missing Authentication on API Invoices Routes
**Vulnerability:** The `/api/invoices` and `/api/invoices/[id]` routes were fully unauthenticated, allowing any unauthenticated user to fetch sensitive invoice data or perform arbitrary PATCH operations to update invoice statuses (Insecure Direct Object Reference).
**Learning:** Routes intended for admin or internal dashboards often fail to include authorization checks during initial rapid development. Centralizing the authentication logic to an `isAuthenticated` helper early ensures consistent token validation across various routes.
**Prevention:** Implement an `isAuthenticated` check using a constant-time comparison helper like `secureCompare` across all sensitive API routes. Ensure a defense-in-depth approach by explicitly failing secure (e.g. HTTP 500 when `APP_API_KEY` is missing from the environment) rather than implicitly bypassing security checks.
